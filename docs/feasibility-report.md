# AI自動売買（FX/株）システム 実現可能性評価レポート

作成日: 2026-07-04 / 対象: 日本在住個人による自己資金でのbot運用

---

## 1. 結論（総合判定と条件）

**総合判定: 条件付きで実現可能。ただし「LLMに売買判断を直接させる」構成は非推奨。**

- **法的側面: 問題なし。** 自己資金・自己判断（bot含む）での売買は金融商品取引業の登録不要（金融庁ガイドブック確認済み）。登録が必要になるのは他人への助言・運用・EA販売等の事業化のみ。
- **技術的側面: 実現可能。** 自動売買を公認するブローカーAPI（OANDA証券、GMOコイン FX、立花証券e支店、kabuステーションAPI等）と成熟したOSSフレームワーク（NautilusTrader、Lean、vectorbt、freqtrade）が揃っている。
- **収益性: 最大の不確実要素。** LLM直接判断型で数ヶ月以上継続黒字を出した独立検証可能な実弾報告は現時点で存在しない。長期・広範囲評価（FINSABER, 2025）では既報のLLM優位性は消失し、実資金実験（Alpha Arena）では6モデル中4つが大幅損失（GPT-5は-75%）。
- **成立条件:**
  1. LLMの役割を「情報処理レイヤー」（ニュース解釈・センチメント抽出・戦略コード生成補助）に限定し、売買判断の主体はルールベース/専用MLに置く
  2. 自動売買公認ブローカーを選定する（DMM FX等の禁止業者は口座凍結リスク）
  3. ウォークフォワード/アウトオブサンプル検証で過学習を排除する
  4. 発注上限・損失上限・kill switchをコード側で強制するガードレールを実装する
  5. バックテスト→ペーパー→少額実弾の段階移行を厳守する

## 2. 最新事例ハイライト（2024〜2026）

**肯定的エビデンス**
- **TradingAgents**（arXiv 2412.20138, GitHub 90.6k stars）: 実際のトレーディング会社の分業を模したマルチエージェントLLM。バックテストでSharpe比・累積リターン改善を報告。ただし公式に「研究目的」と明記、ライブ執行機能なし。
- **Lopez-Lira & Tang**: ニュースヘッドラインからのGPT-4リターン予測は統計的に有意（特に小型株・ネガティブニュース）。ただしLLM普及に伴い超過収益は縮小＝エッジは急速に裁定される。
- **FinGPT**: 金融センチメント分析でF1 0.882。強みはNLPタスクであり、取引での実運用エビデンスはなし。

**否定的・警告的エビデンス（重要）**
- **FINSABER（2025）**: 20年・100銘柄超で再評価した結果、既報のLLM優位性は著しく劣化。原因は銘柄・期間選択によるサバイバル/データスヌーピングバイアスと、レジーム適応の欠如。「フレームワークの複雑化よりトレンド検出とリスク管理が重要」と結論。
- **Alpha Arena（nof1.ai, 2025, 実資金$10,000×6モデル）**: 途中経過でDeepSeek +48%、Qwen3 Max +31%に対し、GPT-5 -75%、Gemini -67%。最終ではQwen3 Maxが約+22%で優勝し途中首位と入れ替わり——短期成績の極端な不安定さを実証。S1.5では6モデル中4つが損失、全モデル勝率25〜30%。主催者総括:「手数料がPnLを支配」「LLMは数値時系列の扱いが根本的に苦手」。首位モデルでもSharpe 0.42程度。
- **Glasserman & Lin**: LLMバックテストのルックアヘッドバイアスと「注意散漫効果」を実証。バックテスト成績を額面通り受け取れない構造的理由。
- **実務家の実地報告**（r/algotrading、検証済み）: LLMニュースセンチメントシグナルは「誤検知70%・正解15%」。金融データサイエンティスト（10年）「LLMのアイデアで過剰適合していないものを見たことがない」。表形式データには専用モデルの方が安く速く正確、というのが一貫した評価。
- **APIコスト構造問題**: TradingAgentsは1回の銘柄分析で16〜22回のLLM呼び出し、キャッシュヒット率ほぼ0%で30〜40%のトークン浪費。推論コスト＋取引手数料の二重コストが期待値を毀損。

## 3. 技術スタック推奨

### ブローカーAPI（日本在住個人・自動売買公認のもの）

| 用途 | 推奨 | 条件・特徴 |
|---|---|---|
| **FX（本命）** | OANDA証券 REST API (v20) | Gold会員・プロコース・残高25万円以上で無料。自動売買を公式に明記。デモ口座あり |
| **FX（次点）** | GMOコイン 外国為替FX API | 無料。GET 6回/秒・POST 1回/秒。WebSocket約定通知あり、IFD/OCO対応、IP制限設定可 |
| **日本株** | 立花証券e支店API | 無料JSON API、自動発注を公式明記、OS非依存（Linux/Python可）。金利コストはやや不利 |
| **日本株（代替）** | kabuステーションAPI (auカブコム) | Professionalプラン必須（条件満たせば無料）、参照系約10req/秒。信用デイトレ手数料0円だが、Windows上でkabuステーション本体の毎日起動が実質必要 |
| **米国株・多市場** | Interactive Brokers TWS API | Python対応、50msg/秒（公式明記）。個人非商用ライセンス。TWS/IB Gateway常時稼働が前提 |

**除外**: 外為どっとコム（約款で自動売買禁止）、DMM FX（約款第7条で自動売買ソフト使用を禁止、違反でアカウント凍結・約定遡及無効）。moomoo証券は日本株取引APIが未確認のため保留。

### OSSフレームワーク

- **リサーチ/バックテスト**: **vectorbt**（v1.0.0、2026年4月。数千パラメータの一括ベクトル化検証。fair-codeライセンスのため商用販売には制限あり）
- **実装・ライブ取引**: **NautilusTrader**（Rust+Python、Python 3.12+。バックテスト→ライブをコード変更なしで移行可能。OANDAアダプタの有無は要個別確認）または **Lean/QuantConnect**（FX含むマルチアセット実績豊富）
- **暗号資産で試す場合**: **freqtrade**（バックテスト〜Dry-run〜ライブ〜FreqAI〜Telegram監視まで無料で完結）
- **非推奨**: backtrader（最終コミット2023年4月、事実上メンテ停止）

### AIの役割分担（最重要の設計判断）

```
[やらせること]                      [やらせないこと]
- ニュース/センチメント抽出・要約     - 売買シグナルの直接生成
- 戦略コードの生成・レビュー補助      - ポジションサイズの決定
- バックテスト結果の分析支援          - リアルタイム価格予測
- 異常検知アラートの文章化            - リスク管理の最終判断
```

売買判断本体はルールベースまたは専用の小型ML（勾配ブースティング等）で構成し、LLM出力は必ず構造化バリデーションを通し、発注金額・頻度の上限はコード側でハード制約として強制する。

## 4. 主要リスクと対策

| リスク | 具体例（検証済み） | 対策 |
|---|---|---|
| **過学習（最頻出の失敗原因）** | バックテスト年利25%のbotが実運用2週間で損失化 | ウォークフォワード検証、アウトオブサンプル検証、手数料・スリッページのバックテスト組込み、パラメータ数の最小化 |
| **バックテストと実弾の乖離** | Alpha Arenaで途中首位が最終で入れ替わり。ペーパー+$2,000の投稿者自身が「ペーパー≠実弾」と警告 | ペーパートレード期間を十分に取り、実弾は失っても許容できる少額から |
| **フラッシュクラッシュ** | 2019/1/3 ドル円が数分で約4円急落、強制ロスカット多発 | 流動性の薄い時間帯（早朝・年末年始・指標前後）の稼働停止、低レバレッジ（国内上限25倍を大きく下回る運用）、口座残高超過損失（追証）の想定 |
| **LLMハルシネーション** | 誤った財務数値の断定事例。LLM接続型はバックテスト再現自体が困難 | LLMを発注判断に直結させない。出力スキーマ検証、コード側ガードレール、重要判断への人間承認フロー |
| **ブローカー規約違反** | DMM FX: アカウント凍結＋約定の遡及無効＋不足金請求 | API/自動売買公認業者のみ使用。APIキーの厳格管理、レート制限遵守 |
| **コスト侵食** | Alpha Arena: 手数料$1,654が利益を圧迫。LLM API呼び出しコストの累積 | 取引頻度の抑制（高頻度戦略を避ける）、LLM呼び出しの最小化・キャッシュ活用 |
| **税務** | — | 国内FXは申告分離課税20.315%・損失3年繰越可。海外業者は総合課税（最大約55%）・繰越不可のため国内業者を選択 |

参考: 失敗事例（EA運用5年で800万円損失等）は多数報告される一方、第三者検証可能な個人の成功事例はほぼ皆無。この非対称性自体を期待値設定に織り込むべき。

## 5. 推奨する段階的アプローチ

### Phase 1: バックテスト（2〜3ヶ月目安）
- vectorbtで戦略仮説を広くスクリーニング → NautilusTrader（またはLean）で精密バックテスト
- **合格基準**: アウトオブサンプル期間で正の期待値、ウォークフォワードで成績が崩れない、手数料・スプレッド・スリッページ込みで黒字、複数のレジーム（上昇/下落/レンジ）を跨いだ検証
- FINSABERの教訓に従い、短期間・少数銘柄の好成績を根拠にしない。LLMを使う場合は学習カットオフとバックテスト期間の重複（ルックアヘッド）を排除

### Phase 2: ペーパートレード（最低3ヶ月）
- OANDAデモ口座（fxTradeデモ）またはfreqtrade Dry-runで、**バックテストと同一コード**をリアルタイム稼働
- 検証項目: 実レートでの約定乖離、システム稼働率（再接続・障害復旧）、レート制限との整合、LLM APIコストの実測、kill switchの動作確認
- **合格基準**: バックテスト成績との乖離が説明可能な範囲に収まること。乖離が大きければPhase 1に戻る

### Phase 3: 少額実弾（6ヶ月〜）
- 全損しても生活に影響しない金額（例: 10〜30万円）で開始。OANDAは残高25万円以上が継続条件である点に注意
- 運用ルールをコードで強制: 1トレード最大リスク（口座の1〜2%）、日次/月次損失上限で自動停止、低流動性時間帯の稼働禁止、レバレッジ上限
- 月次で実弾成績とバックテスト期待値を突合し、乖離の原因分析を行う。増額は「実弾で統計的に有意な期間の黒字」を確認してから段階的に

### 各フェーズ共通の撤退基準
- 実弾で想定最大ドローダウンを超過したら即停止
- ペーパーと実弾の乖離が説明不能なら増額禁止
- 「もう少し回せば戻る」という判断をコードではなく感情で行いそうになったら停止
