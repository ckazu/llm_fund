# 実資金移行ゲート 評価基準（事前登録）

作成日: 2026-07-04
ステータス: ドラフト（承認待ち）
前提: [requirements.md](requirements.md) 5章「実資金移行ゲート（paper-only 原則）」

## 0. 目的と事前登録の趣旨

本書は要件定義書5章の定性的な移行条件（3ヶ月以上の運用・インデックス積立超過・十分な執行遵守率・許容DD内）を、**運用開始前に**定量基準として固定する。事後に成績を見てから基準を緩めるチェリーピッキング（後知恵最適化）を防ぐことが目的であり、本書の基準は運用開始後の「成績が悪いから基準を変える」目的での変更を認めない。基準変更が必要な場合は、変更理由・変更日・変更前後の差分を本書の改訂履歴（末尾）に残し、変更前の期間の成績は変更前の基準で判定する。

## 1. 測定期間

- **最小観測期間**: 仮想執行開始日から連続 **3ヶ月（暦月で3ヶ月、営業日換算で概ね60〜65日）** 以上
- **評価対象期間**: 移行判定を行う時点の直近3ヶ月をローリングで評価する。3ヶ月未満の時点では移行判定自体を行わない（判定不能・継続観察のみ）
- **プロトコル固定境界での分離**: `judgment/schemas.py` の `prompt_version` またはモデル・temperature が変更された場合、変更前後は別の評価期間として分離集計する（技術仕様5章の評価プロトコル固定に対応）。変更をまたぐ期間を1つの評価期間として合算しない
- **中断の扱い**: データ取得失敗・システム障害等で `NO_TRADE` が連続発生し実質的に判断が行われなかった日は観測期間の日数には含めるが、後述の執行遵守率・稼働率の分母には注記のうえ算入する（除外しない。稼働できなかった事実も測定対象）

## 2. 対照群4種との比較方法

要件定義書 FR-5 で定義された4種の対照群を、LLM 運用（`fund`）と**同一日**の同一キャッシュフロー・同一コスト条件（手数料・スリッページ）で並行して仮想運用し、`benchmark_navs` に日次 NAV を記録する。

| コード（`strategies.code`） | 内容 | 役割 |
|---|---|---|
| `index` | インデックス積立（TOPIX連動ETF、例: 1306.T を定期定額買付） | 主比較対象（要件5章1項の基準） |
| `equal_weight` | 売買対象ユニバースの等金額ポートフォリオ（リバランスなし、または月次リバランス） | ユニバース選定自体の寄与を分離するための対照 |
| `momentum` | 単純モメンタムルール（例: N日リターン上位を機械的に組入） | 「単純ルールに勝てるか」の直接対照（要件1章の検証目的そのもの） |
| `random` | ランダム判断（シード固定、再現可能） | 「LLMがもっともらしいだけのランダムでない」ことの検定用。**唯一の必須通過条件**（3節参照） |

比較方法:
1. 各評価期間の期首を基準化NAV=100として指数化し、期末までの累積リターンを比較する
2. 主判定は **`index`（インデックス積立）に対する超過リターン**（要件5章1項）
3. 補助判定として `equal_weight` `momentum` `random` の全てに対しても累積リターン・Sharpe・最大DDを算出し、レポートに常掲する（移行の必須条件ではないが、`random` に対する優位性のみ下記で必須条件とする）
4. 対照群のいずれかに対しても継続して劣後する場合、たとえ `index` に対する条件を満たしていても「規律支援ツールとしての価値」への再評価材料として週次/月次レビューに記載する（撤退基準の判断材料。移行を機械的に妨げるものではない）

## 3. 定量移行基準（3条件、要件5章の具体化）

以下の**すべて**を満たした場合に、実資金移行の「別途計画を立てて判断する」フェーズに進める（自動移行ではなく、満たした時点で人間が計画立案の要否を判断する）。

### 条件A: 対インデックス超過（要件5章1項の具体化）
- 直近3ヶ月の LLM 運用の仮想 NAV 累積リターンが、同期間の `index` 戦略の累積リターンを **上回る**
- 加えて `random` 戦略の累積リターンも **有意に**（詳細下記）上回ること。片方だけでは条件Aを満たしたとみなさない
  - 有意性の簡易検定: 3ヶ月間の日次リターン差分（LLM − random）の平均が0より大きく、その符号検定（二項検定、有意水準5%）で棄却できること。サンプル数が少なく検定力が弱いことは既知の限界として明記し、あくまで「明らかな逆転（LLMがrandom以下）」を排除するためのフィルタとして使う

### 条件B: 執行遵守率（要件5章2項の具体化）
- **執行遵守率の定義**: `executions` テーブルにおいて、`instructions` が生成した指示のうち
  - `filled`（指示どおり、または保守的仮想約定ルールの許容範囲＝IFO 幅内で約定）となった件数 ÷ （`filled` + `skipped` + `partial` のうち乖離が許容範囲外の件数）
  - 分子分母から除外するもの: 有効期限切れで未約定のまま終了した指示（`pending_orders` が `expired` のもの）。これは「人間の不遵守」ではなく「市場が価格に到達しなかった」ため、遵守率の測定対象外とする
  - 許容範囲: `executions.deviation_note` に記録される約定価格の乖離が、指示の `entry_price` に対して ±0.5%以内（日本株の呼値・寄り付き価格変動を考慮した閾値。将来 `criteria`（週次基準）で調整可能だが、変更時は本書に改訂履歴を残す）
- **基準値**: 直近3ヶ月の執行遵守率が **90%以上**
- 90%を下回る場合、原因が「人間の執行不遵守」か「指示自体の非現実性（執行困難な価格指定）」かを週次レビューで切り分け、後者であれば `criteria` の見直し対象とする（切り分け自体は移行判定の必須プロセス）

### 条件C: 最大ドローダウン許容値（要件5章3項の具体化）
- **測定対象**: LLM 運用の仮想 NAV の、評価期間中の最大ドローダウン（ピークからの下落率）
- **許容値**: 直近3ヶ月で **最大DD 15%以内**
  - 根拠: バリデーターの絶対上限（`ABSOLUTE_MAX_POSITION_PCT=25%`, `ABSOLUTE_MAX_TURNOVER_PCT=50%`）と1指示あたり最大損失3%の組み合わせから、複数ポジションの同時逆行を想定した保守的な値として設定。将来のレビューで根拠とともに見直し可能だが、運用開始後に成績を理由に緩める変更は認めない
  - 15%を一度でも超過した場合、直ちに移行判定を「見送り」とし、超過原因を月次レビューで分析する（3ヶ月条件のカウントはリセットしない。あくまで移行判定時点でのゲートとして機能する）

## 4. 撤退基準との関係（要件5章「撤退基準」の補足）

- 6ヶ月運用してインデックス積立に**明確に劣後**の定量化: 直近6ヶ月の累積リターンが `index` を **5%ポイント以上**下回り、かつ直近3ヶ月の条件Aも満たさない状態が継続している場合を「明確な劣後」とする
- この場合、月次レビュー（`review/monthly.py`）で「LLM判断部分の廃止・規律支援ツールへの再定義」または「プロジェクト終了」を提案事項として起票する

## 5. レポートへの常掲項目

`fund benchmark` の出力には、移行判定に必要な以下を毎回算出・掲載する（判定の可否に関わらず常時可視化。要件5章の判定を人間がいつでも確認できるようにするため）:

- 評価期間（開始日・営業日数・3ヶ月到達可否）
- 4対照群それぞれとの累積リターン差
- 条件A/B/Cそれぞれの現在値と閾値・充足可否
- 執行遵守率の内訳（filled/skipped/partial/expired件数）
- プロトコル（`prompt_version`, model, temperature）の変更履歴と評価期間の分離状況
